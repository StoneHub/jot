# Architecture

One SwiftUI menu-bar application owns the microphone and model lifecycle. A shared JotCore module owns SQLite and the Unix socket protocol; the bundled `jot` helper provides CLI/MCP entry points. The JotEngine module holds the recognition engine (`SpeechPipeline` with its `RecognitionCommitWindow`, and the offline `SpeakerPass`) and is the only target that links FluidAudio; the app, `JotRecoveryChecks`, `JotWindowChecks` and `jot-lab` link it, and its package tests run under `swift test`. There is no web service.

AVAudioEngine → mono 16 kHz float samples → bounded capture queue → serialized speech worker → SQLite transcripts. Resume always listens. Held dictation marks a time range in that continuous timeline rather than maintaining a second recording buffer. Delivery is a separate attempt with saved text and a focus-bound target. A failure to acquire or deliver to a field does not delete recognized speech.

`CaptureChunkScheduler` defines short recognition boundaries. `DictationAttempt` defines saved delivery state. `TranscriptStore` persists both recognized words and attempts. `SpeechService` owns recognition and keeps the members the screens and the socket bind to. It delegates to six objects it owns: `CaptureController` (the microphone, input device selection, and the retry after wake), `ListeningTimeline` (the session listening feeds: its id and clock, audio not yet cut into recognition chunks, and the session's audio file), `LiveCleanup` (the queue that rewrites saved live phrases into readable text, and dictation cleanup before insertion), `DictationCoordinator` (one held dictation from key-down to insertion or recovery), `SessionLibrary` (what the screens read and edit on disk), and `SpeakerRecognizer` (the speaker pass queue and People). The microphone sits behind `MicrophoneSource`; it, model loading, microphone permission, inference, delivery, and the clock are dependencies, so the standalone `JotRecoveryChecks` tool exercises the real service without starting a microphone, socket, or UI.

FluidAudio is pinned at `5c19d5e12320e22bbfb7a1877b089d2665a69add`. Parakeet v3 supplies text and word timing, Silero gates likely speech, and streaming Sortformer supplies four speaker probabilities. A single confident speaker is labeled speaker-1 through speaker-4. Multiple active speakers are marked overlap; insufficient evidence is unknown. Speaker state resets on session changes and audio discontinuities. Silero runs first: while it hears no speech in the recognition window, `SpeakerModelFeed` holds that audio back from Sortformer instead of feeding it, keeping the most recent five seconds. Speech releases the held audio to Sortformer ahead of the new chunk, so every word is attributed from the same nearby audio; longer quiet is skipped in whole 0.08-second frames that stay on the session clock, and Sortformer keeps its speaker memory across it. Recognition input is unchanged. Labels are scoped to sessions; naming a speaker also remembers the voice once the pass has one (see People). Early streaming assignments are provisional in quality; this version does not revise persisted segments when later diarizer frames finalize.

When an ambient session ends (ambient off, End meeting, or an automatic pause), an offline speaker pass runs FluidAudio's OfflineDiarizerManager (pyannote segmentation, WeSpeaker embeddings, VBx clustering) over the session file on its own actor, one session at a time, and stores per-speaker segments and one 256-float embedding per speaker in `session_segments` and `session_speakers`. The pass models load with the live models and are released on Pause; a pass that starts after Pause reloads them and lets go when done. The Pause button discards the session file without a pass. End meeting exports as soon as inference finishes, with the live labels; the pass may still be running. Pass speaker ids are renumbered speaker-1, speaker-2 in order of first speech before they are stored. After the relabel, the pass speaker heard most during the session's dictation holds is the user's: its embedding is folded into `UserVoice` (`you.json` in the Jot directory, outside the database, independently of transcript schema changes; a running average like People, trusted after 20 s of held speech) and the speaker is labeled You. In later sessions the nearest unnamed pass speaker within the People threshold of that voice is labeled You, and `TranscriptStore.suggestionContext` gives its rows the user role. You is never remembered as a person; Forget in People or `jot forget you` deletes the file, and the next holds teach it again. `SpeakerPassRelabel` gives each stored word the pass speaker around its midpoint, and once the session's last audio block is recognized and its cleanup has landed, `TranscriptStore.relabelSession` relabels the session's rows off the main thread: a row keeps its id and cleaned text and takes its words' speaker, and a row whose speaker changes inside it splits there, each piece taking its share of the cleaned text. Regroup relabels the same way, from the same segments when the session has them. Relabels run one at a time, off the main thread, on their own queue.

People: `PeopleStore` keeps one row per remembered voice in `people`, a name and one unit-length 256-float embedding that is the running average of every sample saved for it, on its own connection like `SpeakerPassStore`. Naming a speaker adds the session speaker's embedding to the person of that name or creates one. A name given before the pass sits on a live speaker id, which the pass may give to another voice: when the pass relabels, `SpeakerPassRelabel.carriedLabels` moves each name to the pass speaker that took most of its words' time, and the pass remembers that voice under the name. After a pass relabels a session, `PeopleMatcher` pairs session speakers with people by cosine distance (1 - cosine similarity, threshold 0.65, both FluidAudio's SpeakerManager defaults), nearest pair first and one-to-one; only speakers with no name in that session are matched, against people not already named in it; a matched speaker is labeled with the person's name and the person's embedding takes in the new sample. Deleting a person removes only that row. Dictation delivery includes all voices in its marked range and does not filter by speaker identity. The underlying continuous timeline still receives speaker labels.

## Bounds and lifecycle

Ambient speaker attribution uses user-adjustable confidence and minimum-turn duration. Short candidate changes and isolated hesitations retain the preceding confirmed speaker within each inference block; sustained changes create a new turn. This can also merge a genuine short reply. Paragraph pause controls turn grouping, independently of the short capture flush cadence. Dictations may combine nearby same-speaker rows and hide filler-only rows without changing stored source text. Settings persist locally and are exposed by status. `transcript_words` keeps, for each ambient row, its recognized words with start and end times in the session's clock and the diarizer's four speaker probabilities, never audio; Regroup relabels a session's rows from them under the current settings.

- Callback-to-controller queue: 8 seconds of mono float audio.
- No separate held-dictation audio accumulation and no 60-second hold cancellation. Recognized text is saved as chunks finish, including while a shortcut remains held.
- Capture flush: at most three seconds per chunk, or a 0.7-second quiet boundary after at least 0.2 seconds of audio. Recognition keeps two seconds of left context and two seconds of uncommitted tail in RAM, then adds the next chunk (at most seven seconds total). Timed-word ownership prevents already committed speech from being appended again. Releasing dictation, requesting recovery, quiet boundaries, Pause, and session changes flush the retained tail. A flushed chunk shorter than the recognizer's 0.3-second minimum reaches it with trailing silence added, so its words are kept at their own times. Live updates have a three-second cadence; words near a boundary can wait for the next chunk. This is not a claim of instant per-word recognition.
- Pending inference: at most 40 three-second chunks plus an in-flight job and explicit final barriers. Overload records a gap; a held attempt with a known gap retains its partial text rather than automatically inserting it as if it were complete. Explicit review can copy the saved partial text; its gap marker survives relaunch.
- Sortformer timeline is bounded to 1,000 frames; local attribution probabilities are pruned.
- Ambient capture starts a new session when nothing is transcribed for the quiet window set in General (15 minutes by default, or Never). The old session gets its speaker pass at the split; a named meeting runs until it is ended. A session that produced nothing rotates quietly and its audio file is discarded.
- Pause immediately stops the microphone and shortcut listener and finishes saving captured recognition work. The models stay loaded and the lifecycle stays `ready`, so Resume only starts the microphone; `jot status` reports mode `paused` with models `ready`. Agent hook messages are refused while paused. Holding the dictation shortcut while paused starts the microphone for the hold only, in a session of its own with no audio file and no speaker pass, and stops it on release; a release before the microphone is up stops the start. The explicit Unload Models action (menu, `jot models unload`, `models_unload`) invalidates the generation and unloads the models; nothing else does but Quit. It retains recognized speech and failed delivery attempts. UI/CLI/MCP remain available. An explicit Pause remains paused across launch; a sleep interruption resumes previous listening intent after wake independently of Keep Mac awake. A hardware configuration change or stalled input leaves a notice requesting Resume. Selecting an input in Jot instead stops and drains the old microphone, flushes its recognition tail, preserves any held dictation, and resumes under the new selection; an explicit Pause during the transition cancels resumption. Ending a named meeting exports that session while listening continues in a fresh unnamed session.
- Quit stops the app and socket. In-flight/unflushed audio can be lost at quit; already committed transcripts remain.

## Input signal and app replacement

`CaptureController` samples `MicrophoneSignal` from the same microphone drains, publishing only the eight-step meter and changed warning state to the microphone row. Ten seconds below RMS 0.00001 triggers `MicrophoneInputSearch` when automatic switching is enabled. It tries each other physical input once, allows three seconds per candidate, and keeps a candidate with at least 0.1 seconds at RMS 0.0001 or above. This measures input signal, not speech recognition; ordinary room noise prevents a quiet conversation from triggering a search. Missing samples still use the existing stalled-input policy. If every candidate is silent or fails to start, the original selection is restored and the search stays exhausted until signal returns, the devices change, or the user resumes or changes input. Holds defer automatic switching until they finish.

The in-app Update button starts the download immediately. `AppUpdater` verifies the downloaded bundle before asking `SpeechService.prepareForUpdate` to stop intake, save buffered recognition and dictation, and wait for cleanup, speaker passes, and relabeling. `canInstallUpdate` is an internal replacement barrier rather than a disabled-button rule. New holds and suggestions are blocked while finishing. The prior listening state and meeting title are saved for the next launch; a paused app remains paused. A failure before replacement restores listening. A 60-second finishing timeout reports failure without discarding pending work.

## Live cleanup

`PhraseCleanup` groups already-persisted recognition rows into one same-session, same-speaker request. It flushes at a final recognition boundary, a speaker/session change, a gap over 1.2 seconds, or before exceeding 12 seconds or 2,000 UTF-8 bytes across rows. A sentence-ending phrase of at least eight words can flush sooner. An individually oversized row retains the existing model input-limit fallback. Raw recognition stays visible throughout; the capture cadence is unchanged.

One separate live-cleanup worker drains at most eight waiting phrases, without competing for the dictation cleaner's actor. A busy generator gets up to five 200-millisecond retries; overload or invalid output leaves raw text intact. Text-only cleanup can finish after Pause stops the microphone. Installation waits for it to drain; Quit cancels it. Diagnostics distinguish queued work, buffered source rows, and cleanup outcomes without exposing text.

The model edits one joined phrase. Deterministic word alignment distributes its result across stable source IDs, including empty readable text when a filler-only row disappears. `TranscriptStore.setReadablePhrase` commits all derived rows atomically only if every original still exists unchanged. Raw text and timed words remain untouched.

Live uses native selectable text with a 220-millisecond crossfade only for cleanup revisions. Raw appends do not animate. A selected row freezes the displayed feed and revision until selection clears; Reduce Motion disables the fade. Live's minimum paragraph merge gap matches phrase assembly so fragments remain one readable paragraph.

Live reads a session once, when it switches to it. `SessionLibrary` keeps that session in a `LiveFeed`: recognition hands it each row as it is saved, cleanup hands it each cleaned phrase by row id, and it regroups only from the paragraph a change touches, with the rules Sessions and export use. A speaker name, a delete, a regroup, the speaker pass, or a new paragraph pause reads the session again. When a read fails, a switch still moves Live to the new session with no rows, a reload keeps what Live shows, and the next show or reload reads again.

## Delivery and access

A global event tap observes Fn/Globe or a persisted modifier-plus-key shortcut. Fn events pass through unchanged. Custom trigger key-down, repeat, and key-up events are consumed; unrelated keys and modifier events pass through. `ShortcutTracker` owns the physical-key state independently of capture, so modifier-first release finishes only once and autorepeat cannot restart a recording. The shortcut recorder temporarily suspends the global handler while editing. A focus observer and application identity guard the captured field. AX insertion is preferred; the fallback restores the prior clipboard only if it has not been changed since staging. The app never submits the resulting text.

The tracker uses physical event timestamps. Holds begin immediately. A press lasting no more than 0.2 seconds discards only its tiny held intent; two such presses with at most 0.35 seconds between them yield a double-tap event. Fn requests a suggestion only when enabled. No shortcut falls back to recovery insertion. Failed or unverified held dictation stays in the store. `SavedDictationReview` reads a snapshot off the main actor, shows partial-audio and duplicate-paste cautions, and copies only on an explicit click. Reading or copying does not consume the attempt, invoke a language model, start capture or acquire an insertion target. No recent-room-speech fallback or recovery-window setting remains.

`dictation_attempts` stores recognized text, delivery state, and whether there is a known or possible gap, never raw audio. Interrupted attempts with recognized text become recoverable at launch and are marked partial because their unrecognized tail is unknown. Unrecognized audio still in memory can be lost on force-quit; already committed recognition and attempt text remain. Deleting a dictation or session also removes the corresponding recovery records. Held dictation uses word timings when available, falling back to whole overlapping rows only for older transcripts with no word evidence.

Before the store opens, the app takes an advisory `flock` on `jot.lock` in its directory and holds it until quit (`DirectoryLock`). A second Jot, such as a debug or worktree build launched while the installed app runs, finds it held, opens no store and no socket, installs no key tap, and shows the notice; so capture and writable history have one process owner. SQLite operations are serialized. `TranscriptStore` creates every table, and `SpeakerPassStore` and `PeopleStore` open their own connections to the same file after it. The file records its format in `PRAGMA user_version`. Opening a database of the current format (8) preserves existing rows while ensuring additive schema metadata; format 7, which 0.2.5 and 0.2.6 wrote, gains the change feed and keeps every row. Any other nonempty format, older or newer, is refused before a writable connection opens. A read-only inspection includes committed WAL data; refusal preserves the database and its WAL without changing journal mode or permissions, and the launch notice requests a compatible version of Jot. Jot never deletes saved history as a compatibility shortcut. The application-support directory is user-only and the socket is mode 0600; the server checks peer UID, bounds requests/responses, limits concurrent clients, and enforces input deadlines. A second service does not take over a live socket. Dictation creates no audio file. An ambient session appends its 16 kHz Float32 samples to a user-only file under the service directory, `audio/<sessionID>.f32`, only while "Keep session audio until the speaker pass finishes" is on; the file is capped at a continuous two-hour prefix; pending writes are bounded to eight seconds of Float32 audio and 40 packets, including an in-flight write. If admission overflows or a write fails, that offline file is removed and the speaker pass reports it unavailable while recognized speech is retained. The file is deleted the moment the speaker pass has read it, deleted at once by the Pause button or by switching the setting off, and deleted at the next launch if a crash left it behind. Nothing in it is uploaded. With `keepTuningAudio` on (off by default), `SpeakerRecognizer` first copies the finished file to `tuning-audio/<sessionID>.wav` for tuning, and `TuningAudio` deletes those copies once they are more than 30 days old, and the oldest once they pass 10 GB (see [Keep session audio for tuning](TUNING.md#keep-session-audio-for-tuning)). Diagnostics read an explicitly selected existing file.

No model inference sends microphone content to a remote provider. Model preparation downloads model artifacts; future agent reads are separate disclosure decisions. Third-party code and model terms remain their authors' terms: [FluidAudio](https://github.com/FluidInference/FluidAudio), [Parakeet v3 model](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3), and FluidAudio's referenced converted model repositories. This implementation does not relicense those artifacts.

The SwiftUI app uses a single `Window` scene, disables automatic tabbing, and switches activation policy between regular (Dock visible) and accessory (window closed). The menu-bar popover and window share the same service controls. Published model metadata is separate from installed-cache provenance.

## Suggestions

`SuggestionCoordinator` owns one explicitly requested suggestion at a time: double-tap Fn (or the optional shortcut) captures the focused field through `DictationInput`, reads it, and builds one prompt for Apple's on-device model through `ModelCallGate`. The prompt's sources come from one window, `suggestionWindowMinutes` (ten by default): the text visible above the field in its window, read through Accessibility when that setting is on; every transcript row spoken in the window, from `TranscriptStore.suggestionContext`, with its speaker label, joined into turns (`SuggestionContext`: rows from one voice at most 1.5 seconds apart are one source; ambient rows heard during a dictation hold are left out as copies of it; the voice heard during a session's holds is the user's; any other unnamed voice is described as possibly the user); and messages handed Jot through `context.add` or the optional Claude Code and Codex hooks, held by one `AgentContext`. Hooks use submitted prompts and `last_assistant_message` from their event payload; they never read transcript files. The CLI bounds input and sends it over the same-user socket. `AgentContext` retains role, source, conversation, turn and working directory, deduplicates retried events, and remains memory only: one message is at most 8 KiB, the whole set at most 64 KiB or 128 messages, oldest dropped first, and messages older than the window are dropped on read. An agent source enters a suggestion only when one compatible conversation's latest substantial reply matches text visibly above the focused field; absent or ambiguous matches exclude all agent messages. Source changes, eviction, clear and expiry invalidate a card using those messages. `SourceSelector` keeps at most twelve sources and 6,000 bytes, and whole sources only. When the bound forces a choice, a pinned selection comes first, then the field's own context (the text on screen and the turns of the agent conversation the field belongs to; the coordinator names the matched conversation on the target), then the user's own words, then the sources that share at least two distinctive words or a three-word run with the field's text, notes and own context (`HeardSpeech.Terms`), most shared first; time only breaks ties. So a video playing after the user's spoken reply, or a phone call after a dictated note, fills what room is left rather than taking theirs. The conversation id is taken off the target again before the prompt is built. `SuggestionPlan` picks the mode before any model call: a selection with text is rewritten (draft), other text is continued at the cursor (continuation), and a blank multi-line field gets a reply. Reply and continuation need at least one selected source. The card shows the result; Tab inserts it at the cursor or replaces the selection it was drafted from, after re-reading the field and the rows it used.

`SuggestionKeyTracker` in JotCore decides what each key does while a card is up, with no Accessibility or AppKit call. Tab accepts a ready card; Escape cancels a loading or ready card; both are consumed along with their paired key-up, so the app never sees them. Any other key dismisses the card and reaches the app. A "No suggestion" notice is dismissed by any key, Escape included, without consuming it: there is nothing to cancel, and the Escape was meant for the app. The macOS screenshot chords leave the card up and pass their keys to the screenshot tool. The event tap stays enabled whenever hold dictation or Suggestions is on, because the double-tap Fn request and the Tab acceptance are key events; with both off it is removed. While a card is up, `SuggestionCoordinator` re-reads the field four times a second through `SuggestionFieldReader`, off the main actor: each read goes to a fresh Accessibility element reference with a 5 ms timeout per call, so a stalled app cannot hold the main thread, and the reference insertion uses keeps its default timeout. The rows behind the card are checked once a second; acceptance re-reads both before inserting.

`SuggestionHistory` persists one text-free receipt per request in the existing SQLite file, capped at 200 rows and 14 days. A receipt stores only typed field role, plan, mode, template ID, source kind counts and actual selected UTF-8 byte totals, exclusion reason counts, agent match state, bounded timing, outcome, and user action. Immutable entries are validated before saving; revisions prevent out-of-order async writes from replacing newer state. Opening the store marks unfinished requests interrupted. No field, screen, transcript, prompt or output text, conversation IDs, or working directories enter this table. The same-user CLI reads it through `jot suggestions`.

For a selection rewrite only, `TranscriptStore.heardRows` reads ambient rows inside the same window on a background executor. `HeardSpeech.match` uses distinctive words and three-word runs shared with the selected notes; it keeps the matching sentence and backing row IDs. `HeardSpeech.adding` removes any overlapping grouped speech turn and stays within the twelve-source, 6,000-byte limit. The prompt places the user's selected notes after sources and directs the model to restore only the quoted words. The card identifies this source as “what Jot heard”; source rows are checked again before preview and Tab insertion. The **Use matching speech** setting disables this lookup without changing ordinary context retrieval.

## Personal vocabulary

`PersonalVocabulary` in JotCore validates entries and performs one pass over the original recognized string. Matches are case-insensitive literal whole phrases, with flexible whitespace and Unicode letter/mark/number boundaries. Overlaps resolve leftmost first, longest at the same start; inserted replacements are never matched again. Duplicate matching phrases are rejected, including disabled entries. Empty “Heard as” uses the preferred spelling as its matching phrase.

Jot stores the Codable vocabulary separately in its `personalVocabulary` preference. A load error preserves existing data and blocks editing rather than overwriting unreadable entries. Fn captures a value snapshot when dictation begins. The worker saves original transcripts first; the held attempt applies the vocabulary snapshot before delivery. Recent-window insertion uses current vocabulary. The Vocabulary preview uses the same matcher.

## Performance diagnostics

`PerformanceDiagnostics` in JotCore keeps bounded numeric samples, typed lifecycle events, and per-job timings. SpeechService feeds it from the existing sampler, captures lifecycle transitions, and measures job queue/inference/completion time using monotonic uptime. Reports are exposed through `jot diagnostics` and `speech_diagnostics`; they have no SwiftUI view or published view model. See [local performance investigation](PERFORMANCE.md) for limits and measurement semantics.

Debug and Release use the same product UI, with no DevFeedback picker, overlay, feedback tags, or generated row keys.

## Concurrency, delivery and evaluation

Jot, its recovery/window checks, CLI and JotCore compile in Swift 6 mode with complete strict concurrency. Xcode treats warnings as errors. UI delegates and lifecycle cleanup are isolated to the main actor; store execution and shortcut classification remain on their existing workers. A prepared offline speaker manager is immutable after loading, and its retained owner keeps an in-flight pass valid when the service unloads its reference.

Accessibility identities cross workers through `AccessibilityElement`. Workers use fresh references before setting timeouts. Captured field references keep a 5 ms timeout for focus checks and setters. Field-value/hint reads, full-field verification and Unicode event preparation run off the main actor; every await is followed by request/focus validation before a write or a result is accepted. Unicode dispatch yields between its 20-unit events. A timed-out or ambiguous AX write never triggers another insertion. `FieldInsertionReadback` decides verification and retry eligibility from transient snapshots without persisting text.

Production suggestions expose reply, continuation and selection drafting. `JotSuggestionEvaluation` owns the corpus's historical shell mode, authored oracle selection, the two-second experiment deadline and cancellation grace waiting. Production retrieval and oracle evaluation share deterministic ranking and whole-source bounds. The committed corpus parity test checks selected sources, exclusions and exact model-request hashes across all four experiment/production selection configurations.

Use dictation for the configured shortcut feature; Fn names only its physical gesture. `dictationRequested` and `dictationEnabled` are the canonical status fields. The old `fnRequested` and `fnEnabled` status fields remain compatibility aliases, and the existing `fnRequested` preference key is retained. Forgetting a remembered voice uses `people.forget`; `people.delete` remains a socket alias for existing clients. Capture means microphone intake; listening is the user's continuous-capture intent; an ambient session is the persisted session rather than held dictation. Raw transcripts and readable cleanup are distinct stored representations.

Public types and independent production owners have named files. Nested types and related view helpers remain with their owner. Existing transcript schema, history, user voice and preference values are preserved.
